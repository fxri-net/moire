# 发版流程

发版分两段：先把版本号与更新日志落到主分支，再出产物、写分发分支、打标签。两段之间走一次完整门禁，任何一步失败都停下修，不靠后一步补。

## 前置

- 变更集与更新日志由**全局** `@fxri/toolkit` 提供，项目内不装 `changesets`，也不设对应 npm scripts。
- 发版在 `main` 分支进行，`pnpm release` 会校验分支、工作区干净、标签未重复。

```sh
# 一次性安装（全局，所有项目可用）
pnpm add -g @fxri/toolkit
```

## 1. 记录变更

一处改动产生一个变更集，放在 `.changeset/` 下：

```sh
toolkit changelog
```

正文逐条写成 `- 类型：描述`，类型取自仓库约定的字典（新增 / 修改 / 修复 / 优化 / 清理 / 文档）。frontmatter 的 bump 级别按改动量级选择：破坏性变更 `major`，新能力 `minor`，其余 `patch`。

::: warning 条目不写列表标记会被合并
changesets 会把无 `- ` 标记的裸行并入相邻条目作缩进续行，整段正文塌成单一条目，只有首行参与分组。逐条加 `- ` 是硬要求，`toolkit tasks check` 会在归档前拦下这类问题。
:::

## 2. 门禁

```sh
pnpm verify
```

这一条与 CI 同源：类型检查、代码规范、格式校验、单元测试、构建产物、示例类型依次执行，任一失败即中止。本地不通过就不要进入下一步。

## 3. 升版本与写日志

```sh
toolkit changelog version
```

它会消费 `.changeset/` 下的变更集，升 `package.json` 版本号，并在 `CHANGELOG.md` 顶部写入新版本块与中文分组标题（🚨 破坏性 / ✨ 新增 / 🔧 修改 / ⚡ 优化 / 🐛 修复 / 🧹 清理 / 📝 文档 / 🔗 链接 / 📦 依赖）。

生成结果需要人工过一遍：补写必要说明、调整分组归属、删掉对使用者无意义的内部条目。

## 4. 归一与镜像

```sh
toolkit changelog --history format
pnpm sync:changelog-doc
```

第一条按「同组顶层条目逐行相邻」重排历史块，消除人工润色留下的空行；带 `--history` 才会改历史块，缺省只动新块。第二条把根 `CHANGELOG.md` 镜像成文档站的[更新日志](./changelog)，页头带「请勿手改」提示。

::: tip 选项必须写在子命令之前
`toolkit changelog --history format` 生效，写成 `toolkit changelog format --history` 会被 changesets 静默忽略，表现为「无 CHANGELOG 需要更新」。
:::

## 5. 单独提交版本与日志

版本号、`CHANGELOG.md`、`docs/changelog.md` 与消费后的 `.changeset/` 一起提交，提交信息用 `新增：发布 1.0.0` 这一格式。代码改动与发版准备分开提交，回滚时边界清楚。

## 6. 出产物

```sh
pnpm release
```

脚本按序执行：

1. 校验工作区干净、当前在 `main`；
2. `pnpm build` 重新构建（`--skip-build` 可跳过，仅在刚构建过时使用）；
3. 逐项校验 `dist/manifest.json`：版本号一致、文件存在、字节数与 sha256 匹配、目录内没有清单外文件；
4. 在临时工作树里更新 `dist` 分支：清空上一版、拷入产物与 `LICENSE`/`NOTICE`/`README.md`、写入 `.gitattributes`、提交；
5. 在分发提交上打附注标签 `vX.Y.Z`，并打印推送命令。

同名标签已存在时脚本直接报错，说明版本号没升。

## 7. 推送

```sh
git push origin main dist vX.Y.Z
```

推送前确认三样一起走：主分支的版本提交、`dist` 分支、版本标签。只推其中一部分会造成「标签指向的分发提交不存在」或「版本号已升但没有产物」。

## 检查清单

| 阶段   | 通过标准                                            |
| ------ | --------------------------------------------------- |
| 变更集 | 每条以 `- 类型：描述` 开头，bump 级别与改动量级一致 |
| 门禁   | `pnpm verify` 全绿                                  |
| 日志   | 新版本块分组正确，`docs/changelog.md` 已同步        |
| 产物   | `manifest.json` 校验通过，`dist` 分支只含清单内文件 |
| 推送   | `main`、`dist`、`vX.Y.Z` 三者同时到位               |

## 常见问题

| 现象                                      | 原因与处理                                        |
| ----------------------------------------- | ------------------------------------------------- |
| `pnpm release` 报「工作区存在未提交改动」 | 先把版本与日志提交，再出产物                      |
| 报「请在 main 分支发布」                  | 切回 `main` 或改用临时分支验证流程                |
| 报「标签 vX.Y.Z 已存在」                  | 版本号未升，补一个变更集重跑第 3 步               |
| 分发后清单校验对不上                      | 分发目录被换行转换或手改过，重新按标签拉取        |
| 日志块条目挤在单组                        | 变更集里有裸行，按第 1 步补 `- ` 后重跑第 3、4 步 |
