# 发版与分发通道

批次：第 7 批　计划位置：7 / 7　前置：类型产物与迁移文档

## 背景

接入方目前把本仓源码副本连同压缩的 `.git` 目录一并提交，升级时需解压、拉取、再压缩、再提交，链路长且易错；实际运行时只加载一两个压缩产物。本批建立「只交付产物」的分发通道，让接入方按 tag 拉取，升级变为一次 `git subtree pull`。

## 实施方案

1. changesets 接入：新增 `.changeset/` 与发版脚本，先以 `1.0.0-alpha.N` 预发，验证后落 `1.0.0` 正式版。
2. `dist` 孤儿分支：只承载产物、`manifest.json`、`LICENSE`、`NOTICE`、`README`，不携带源码与历史；每个正式版本打对应 tag。
3. 发版脚本：从主分支构建后把产物写入 `dist` 分支并提交，校验和写入 `manifest.json`。
4. 接入说明：给出 `git subtree add --prefix ... --squash` 与后续 `git subtree pull` 的命令与注意事项，并说明锁 tag 的升级与回滚方式。
5. 演练一次：从 `dist` 分支按 tag 拉取到临时目录，核对校验和与产物可用性。

## 影响范围

- 新增：`.changeset/`、发版与推送脚本、`dist` 分支、接入说明文档
- 主分支运行代码不变
- 私有 git 端点在开发机、服务器与 CI 三处的可达性尚未验证，是启用本通道的唯一外部前置

## 验证方式

- `pnpm verify` 全绿
- `1.0.0` tag 存在，且 `dist` 分支对应提交的产物校验和与 `manifest.json` 一致
- subtree 拉取演练成功，拉下的产物在示例页可用
- 若私有端点不可达，退回「产物包 + 校验和」的离线分发方式并记录原因
