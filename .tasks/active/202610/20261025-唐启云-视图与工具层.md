# 视图与工具层

批次：第 4 批　计划位置：4 / 7　前置：适配与字段层

## 背景

`view/mould/view/list/layui.js` 共 639 行，是耦合最深、回归风险最高的文件；`view/mould/tool/*` 承载选择、编辑、跳转等操作，操作类型以散写字面量区分，缺少可测边界。本批把视图装配与工具集改为契约驱动，并把最复杂的列表装配拆成「纯装配」与「薄渲染」两层。

## 实施方案

1. `src/views`：定义 `ViewAssembler` 契约，实现列表与表单两个装配器；输入为 schema 描述，输出为与字段注册表对接的装配结果。
2. 列表装配器按「纯装配（可单测、无 DOM 依赖） + 薄渲染（只调 adapters）」两层拆分，逐段对照旧实现迁移，不留行为差异。
3. `src/tools`：迁移 `mould/tool` 全部工具，选择 / 编辑 / 跳转等操作类型改用具名枚举，禁止散写字面量。
4. 工具集统一返回结构化结果，不再以 `false` 兼表失败与空值两种语义。

## 影响范围

- 新增：`src/views/`、`src/tools/`
- 不改动 adapters 与 fields 的对外契约
- 列表与表单的装配入口由旧 `fxView` 链式调用改为装配器调用

## 验证方式

- `pnpm verify` 全绿
- 列表与表单装配结果做快照测试，覆盖分页、排序、空数据、多选四种场景
- 工具集单测覆盖每个操作类型与失败分支
- 旧实现与新实现在同一 schema 下的装配结果逐项比对一致
