# 类型产物与迁移文档

批次：第 6 批　计划位置：6 / 7　前置：入口切换与旧代码清理

## 背景

新链路已可产出运行产物，但接入方需要类型提示才能低成本迁移；同时旧 API 与新 API 差异较大（全局命名空间改为单一 `window.moire`、链式调用改为装配器、数字编码改为具名枚举、`fxy-*` 改为 `data-moire-*`），必须给出逐条对照，否则迁移只能靠猜。

## 实施方案

1. 类型产物：`tsc --emitDeclarationOnly` 输出 `.d.ts`，覆盖 `moire` 全部公开面；另产 `moire.esm.js` 供现代构建接入。
2. `manifest.json`：记录版本、构建时间、产物清单与各自校验和，供接入方校验。
3. 迁移对照表：旧 API → 新 API 逐条映射，至少包含五组：五个全局命名空间 → `window.moire`；`deployer` / `caller` 链式调用 → 装配器与字段实例；13 个合并数字码 → 五维选项（逐行对照）；URL / 时间 / 填充 / 选择四类数字码 → 具名枚举；`fxy-*` → `data-moire-*`。
4. `examples/`：提供表单、列表、自定义插件三个可运行最小示例，均通过类型检查。
5. 对照表与示例进仓库文档，作为第 7 批发版说明的引用源。

## 影响范围

- 新增：类型声明产物、`moire.esm.js`、`manifest.json`、迁移对照文档、`examples/`
- 不改运行逻辑
- 文档中不出现外部仓库实名，接入方一律以通用措辞指称

## 验证方式

- `pnpm verify` 全绿
- 对 `examples/` 单独跑一次 `tsc --noEmit`，确认类型声明可用
- 三个示例页在浏览器冒烟通过
- 对照表逐行核对：每条旧 API 在旧代码中确有对应，每条新 API 在新产物中确实导出
