# 入口切换与旧代码清理

批次：第 5 批　计划位置：5 / 7　前置：视图与工具层

## 背景

四个前置批次完成后，新链路已覆盖内核、字段、视图与工具，但产物仍由旧链生成、入口仍是 `document.write` 同步注入四个脚本，全局挂载 `fxApp` / `fxBase` / `fxView` / `fxLocal` / `fxSession` 五个命名空间。本批完成入口切换并一次性删除旧代码，使仓库只保留新结构。

## 实施方案

1. `src/entries`：编写 IIFE 单产物入口，完成 `window.moire` 装配、内置插件注册、内置字段注册与版本注入。
2. `vite.config.ts` 正式接管产物：输出 `moire.min.js`（IIFE + terser），layui 与 jQuery 保持 external 全局。
3. 删除旧代码：`base/`、`view/`、`build/`、根目录旧 `moire.js`；`package.json` 的 `main` / `files` 改指新产物。
4. 全仓残留清理：确认无 `document.write` 加载链、无五个旧全局命名空间、无旧构建脚本引用。

## 影响范围

- 删除：`base/`、`view/`、`build/`、旧 `moire.js`
- 修改：`package.json` 的 `main` / `files` / `build` scripts、`vite.config.ts`
- 产物名保持 `moire.min.js`，全局只保留 `window.moire`，旧全局命名空间不再提供
- 本批是唯一允许破坏兼容的节点，接入方适配在第 6 批对照表发布后进行

## 验证方式

- `pnpm verify` 全绿
- 产物在最小 HTML 页面冒烟：能装配插件、能渲染一个表单与一个列表
- 全仓搜索确认无 `document.write`、无 `fxApp` / `fxBase` / `fxView` / `fxLocal` / `fxSession` 残留
- 产物体积与改动前对比留档，确认未引入意外依赖
