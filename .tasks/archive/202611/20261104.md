# CI 补手动触发与条件化

批次：本仓本轮门禁与 CI 收敛（前置：无）

## 背景

1. 两个工作流只有 `push` / `pull_request`，平台丢事件时无手动补跑入口。
2. 聚合门禁每次本地运行都全量安装依赖并构建文档站，多数改动与二者无关，属可省的时间。

## 实施方案

1. `.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml` 各增加 `workflow_dispatch:`，附一行中文注释；`deploy-docs.yml` 现有「不做 paths 过滤、每次推送全量重建」策略保持不变。
2. `scripts/verify.mjs`：
   - 新增 `--full` 与 CI 判定；CI 与 `--full` 恒全量。
   - 安装条件化：本地 `pnpm-lock.yaml` 不比 `node_modules/.pnpm/lock.yaml` 新时跳过。
   - 文档构建条件化：本地仅在改动触及 `docs/`、`src/`、`README.md`、`package.json`、`pnpm-lock.yaml` 时执行（站点配置直接引用源码侧枚举与版本，故 `src/` 计入触发面）。
   - 跳过时输出 `⊘` 行与原因，不静默。
3. 不建变更集：门禁编排与 CI 配置改动，用户不可感知。

## 影响范围

- 代码：`.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml`、`scripts/verify.mjs`。
- 代码（执行中发现的连带修复）：`package.json` 的 `format:check` 增加 `--end-of-line auto`——本仓 `.prettierrc` 在 Windows 检出为 CRLF，默认 `endOfLine: lf` 会让格式校验恒红（Linux CI 为 LF 故不暴露），属同日发现的同类环境相关缺陷。
- 无触达：`src/`、`docs/` 手写页、`README.md`、`CHANGELOG.md`。
- 变更集：不建（用户不可感知）。

## 验证方式

- 本地：安装与文档步骤按改动面跳过并打印原因；`--full` 强制全量通过。
- `CI=1`：安装与文档步骤不被裁剪。
- 触及 `docs/` 或 `src/` 时文档步骤自动执行。
- `pnpm verify` 全绿（归档后复跑）。

## 实施结果

- 两个工作流各加 `workflow_dispatch:` 并附注释；`deploy-docs.yml` 的「不做 paths 过滤、每次全量重建」策略保持不变。
- `scripts/verify.mjs`：新增 `--full` 与 CI 判定；安装按 lockfile 时间戳条件化；文档按 `docs/`、`src/`、`README.md`、`package.json`、`pnpm-lock.yaml` 判触发；跳过时打印 `⊘` 与原因。
- 验证：本地首轮 `package.json` 被改动 → 文档步骤正确触发、安装跳过；`CI=1` → 安装与文档均执行；`--full` 同 CI 口径。
- 连带修复：`format:check` 加 `--end-of-line auto`，消除 Windows 检出下 `.prettierrc`（CRLF）导致的格式校验恒红；`scripts/verify.mjs` 已按本仓 prettier 规则重排。
