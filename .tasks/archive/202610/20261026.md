# 产物清单记录源码提交

## 计划位置

前七批工程化改造与文档站、双平台流水线之后的独立增强；方案经确认取「保持 dist 分支 + 标签打在产物提交」的形态，补溯源能力。

## 背景

产物经 `dist` 孤儿分支按 `vX.Y.Z` 标签交付，标签指向产物提交而非 main 提交，因此从产物侧无法得知它由哪个源码提交构建。`manifest.json` 目前只记 `version` 与 `builtAt`，缺少源码提交这一项；`--skip-build` 时也没有任何机制拦住「拿上一次构建的产物发布」。

## 实施方案

1. `scripts/manifest.mjs`：清单增加 `commit` 字段，取 `git rev-parse HEAD`；取不到 git（源码包解压等场景）时写空串并告警，不阻断构建。
2. `scripts/release.mjs`：`verifyManifest` 增加一条校验——`manifest.commit` 必须等于当前 `HEAD`，不一致即报错，避免发布旧产物。
3. 文档同步：`docs/distribution.md` 的分发形态与校验产物章节补 `commit` 字段；`docs/release.md` 的出产物步骤补这条校验。

## 影响范围

- 修改：`scripts/manifest.mjs`、`scripts/release.mjs`、`docs/build.md`、`docs/distribution.md`、`docs/release.md`、`docs/migration.md`
- `dist/manifest.json` 结构新增 `commit` 字段，从下次发版起生效；已发布的 1.0.0 清单无该字段
- 不改运行期代码、类型声明、分发方式与标签形态

## 验证

- `pnpm build` 后核对 `dist/manifest.json` 的 `commit` 与 `git rev-parse HEAD` 一致
- `pnpm verify` 全量通过
- `toolkit tasks check` 通过

## 完成情况

- `scripts/manifest.mjs` 新增 `sourceCommit()`，清单在 `version` 与 `builtAt` 之间写入 `commit`；无 git 环境写空串并告警
- `scripts/release.mjs` 的 `verifyManifest` 增加 HEAD 一致性校验，不一致时报错并提示重新构建
- `docs/build.md`：产物表、构建步骤描述、清单结构样例与说明段同步 `commit`
- `docs/distribution.md`：分发形态与校验产物章节补 `commit` 的溯源用途
